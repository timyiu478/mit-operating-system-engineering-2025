# Question

For this lecture, read the kernel files buf.h, fs.h, bio.c, fs.c, sysfile.c,
and file.c. You may find Chapter 10 of the book useful in understanding the
file system code.

It's possible, by commenting out one line in in fs.c, to cause xv6 to behave
(incorrectly) like this:

```
$ echo aaa > a
$ echo bbb > b
$ cat a
bbb
```

This behavior is incorrect because file a should contain aaa.

Which line can you comment out to cause this behavior?

Optional challenge: what pair of lines can you comment out in the xv6 kernel to
produce this behavior?

```
$ echo aaa > a
$ rm a
$ echo bbb > b
$ cat a
bbb
```

Of course cat a should result in cat: cannot open a, and should not print b's
content.

# Answer

If the [fs.c:78](https://github.com/mit-pdos/xv6-riscv/blob/riscv/kernel/fs.c#L78) line is commented, it will cause xv6 yo haave incorrectly like this because file system realloc the same data block for file a to file b:

```
$ echo aaa > a
$ echo bbb > b
$ cat a
bbb
```

To produce this behavior,

```console
$ echo aaa > a
$ rm a
$ echo bbb > b
$ cat a
bbb
```

We need to keep commenting fs.c:78. Also, we need to comment the following lines in the `sys_unlink` function:

```c
222   memset(&de, 0, sizeof(de));
223   // if(writei(dp, 0, (uint64)&de, off, sizeof(de)) != sizeof(de))
224     // panic("unlink: writei");
225   if(ip->type == T_DIR){
226     dp->nlink--;
227     iupdate(dp);
228   }
229   iunlockput(dp);
230
231   // ip->nlink--;
232   iupdate(ip);
233   iunlockput(ip);
```

We commment out line 223 and 224 can keep the directory entry of of file a in root directory.
We comment out line 231 so that ip->n so that itrunc() => bfree() will not be called.

The bfree() will panic when it is freeing a free block.

Since we commentted the line fs.c:78, the block is not marked as used so bfree() can't be called.

```c
 91 // Free a disk block.
 92 static void
 93 bfree(int dev, uint b)
 94 {
 95   struct buf *bp;
 96   int bi, m;
 97
 98   bp = bread(dev, BBLOCK(b, sb));
 99   bi = b % BPB;
100   m = 1 << (bi % 8);
101   if((bp->data[bi/8] & m) == 0)
102     panic("freeing free block");
103   bp->data[bi/8] &= ~m;
104   log_write(bp);
105   brelse(bp);
106 }
```
